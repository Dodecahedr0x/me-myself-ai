# Workspace accounts

Implementation contract for US-01, US-03 and US-07. This updates [browser sign-in](browser-signin.md).

## Slack

A verified user token or browser grant connects the workspace and discovers its public and private channels accessible to the user token. Adding an account requires no channel selection. Reconcile membership periodically, preserving channel IDs, tasks and checkpoints when a channel is renamed. Stop polling channels that disappear from a complete inventory. A failed inventory retains the previous one. Workspace disconnect removes the grant and its monitored channels. Direct messages are outside the channel inventory.

Connect Slack accepts a user access token, a rotating user refresh token, or both. Rotation uses the client ID of the Slack app that issued the token. Confidential clients also supply their client secret. Verify the Slack workspace and user before replacing a connection. With a usable access token, verify it and enumerate channels before spending the refresh token. A refresh-only connection obtains a user access token from Slack. All channels share one Keychain grant. Renew before Slack’s reported expiry, persist each replacement refresh token, and serialize concurrent renewals. Credentials stay out of dashboard state, browser storage and activity history. Verify two successive renewals, mismatched identities, cancellation and access-token-only compatibility with fixtures.

## Google

The Google account chooser and consent screen run in the browser. Connect Google opens the account chooser without asking for developer credentials. A preconfigured desktop client uses the direct Google API transport. Otherwise the desktop app runs the published Gemini CLI Google Workspace MCP connector locally. The connector handles browser consent and its own isolated encrypted profile for each account. MeMyselfAI uses its supported tools for Gmail, Drive and Calendar, including sending a reviewed reply or creating a reviewed deadline event. With a publisher-configured Google desktop client, Connect Google requests read access to Tasks and personal Contacts in the same consent flow as Gmail, Calendar and Drive. Choosing the same account upgrades its existing connection in place, including when reconnecting from a bundled extension profile. A cancelled or rejected sign-in retains the previous connection. The extension’s published registration lacks access to Tasks and saved Contacts. A build that uses it lists only the services it can read. Cancellation, rejection or disconnect disposes of the corresponding connector profile. Reconnection verifies the original Google address before replacing its profile. Credentials obtained for unrelated applications stay with those applications. Existing mail connections survive upgrades and can reconnect for additional permissions. Each connected account displays its granted services. Google grants access per service and scope.

Resolve the account independently of People profile metadata through an already granted service using Drive’s current user, Gmail’s own mailbox profile or the signed-in user’s primary calendar. Request no extra scopes. Every new connection asks Google to select the account. Distinct Google identities receive distinct connection IDs, and signing in to the same identity reconnects its existing row.

Gmail supplies messages and approved replies. Calendar, Drive (including Docs, Sheets and Slides), Contacts and Tasks supply recent account activity. A task triggered by a native Drive file can read a bounded document, spreadsheet or presentation excerpt. Calendar supports creating events on the account's primary calendar. Service polling failures are isolated. Deadline proposals show the calendar account, title, start and end before delivery. A dated commitment proposes a 15-minute event at its deadline. A task may also explicitly request a calendar event. With several candidate accounts, use the originating Google account or ask the user. Dry mode requires version-specific approval. Direct API event creation uses a stable provider ID. Connector event previews include a task reference in the description and disable attendee notifications. The executor checks for that reference in the reviewed time slot before creating the event and records the provider receipt. Ambiguous delivery requires reconciliation. The bundled connector discovers primary-calendar occurrences within the scan window and Drive files by modification time. It verifies service read access before listing a service as connected.

Verify automatic channel enrollment, channel additions and removals, identity checks, partial Google consent, incremental activity, calendar routing and date validation, dry-mode approval and repeated delivery.

Verify that upgrading a fixture account preserves its connection ID and history, queues a fresh review of affected calendar previews and discovers both Tasks and Contacts under that one connection.
