# Desktop workspace

**Status** — Implementation contract. Covers [US-01 through US-16](../user-stories.md) at the dashboard boundary. The draft [inbox, focus card and board](inbox-experience.md) will replace the Home and Tasks layout described here. Until it ships, this spec describes the implemented app.

Home summarizes the task queue, pending suggestions, recent activity, projects and style reviews. Tasks needing attention appear first. The status counts open the corresponding filtered queue. Home offers task creation and shows the current agent provider and delivery mode. Its Connections section contains a single **Manage connections** button that opens the Connections page, where the user can choose providers and inspect accounts. Tasks also offers suggestions and the full searchable queue. Activity contains the full timeline.

Use warm white surfaces, graphite text and green actions throughout the workspace. Task status is written out, with an amber margin marker on rows that need a decision. Keep the task title and preview together. In activity logs, align local event times in a column next to the event description and show the date for earlier days. At narrow widths, filters and actions can wrap. Keyboard focus stays visible on rows, links and controls.

Each connected account opens its own chronological activity log. Slack workspaces include their monitored channels and GitHub accounts include their repositories. Each Google address and enabled desktop chat source has an independent log. Use stable source IDs so renaming an account cannot mix its history with another account. Include sync outcomes, observed activity and related task or delivery records. Previously recorded events can be attributed when their stored source is known. Opening a log preserves access to the full timeline via its connection filter. A connection with no recorded activity has a distinct empty state.

Task details show the trigger, available results, completion evidence, linked activity, commitments, and worktree when present. A review presents the full proposed content, sending account, destination, and action version. Approving submits exactly the version on screen. Changing a proposal through feedback requires another review. A question can be answered locally. Failures expose recovery options consistent with the recorded delivery state.

Connections, projects, decision rules, delivery settings and Markdown revisions are editable from the workspace. Connections are workspace-wide. Setup and reconnection ask for the provider and source. Project selection appears on tasks and decision rules. New connections offer provider sign-in first. GitHub can reuse the local GitHub CLI account or start a browser login. Slack accepts a user token. Google uses browser consent for Workspace services. Before saving, the user sees the verified account and connects their GitHub account, connects the Slack workspace, or confirms their Google account. Users can cancel, retry or enter credentials manually. Existing connections can be edited or reauthenticated. GitHub’s account row expands to show repository sync status. Browse work pages through open issues, pull requests and review requests. Review for work submits a monitored item to discovery. Passwords and authorization credentials stay out of browser storage. A missed-work report is accessible from activity. Activity and source text render as text. Dialogs are keyboard accessible and polling preserves open forms and the proposal the user is reviewing.

The sidebar links to agent provider settings. Settings shows the configured CLI and lets the user select Claude Code or Codex CLI independently of delivery mode. Both choices are available even if their executable is missing. The editor shows installation status, explains how to sign in using the CLI, and explains that the CLI may send supplied task context to its configured AI service. The user can recheck installation after installing a CLI. A pending style suggestion can be approved or declined. An investigation report links to each recovered task available in the queue.

## Acceptance criteria

- A question in Home or Tasks shows one short prompt and up to three short answer buttons. Opening the task shows the context and what each answer means. A user can select an answer from either view or enter their own. Questions requesting a new fact may have no suggested answers. Clicking a choice records an answer only for the version shown. A stale choice fails without answering a newer question. Existing long questions remain answerable while the app prepares a compact presentation.

- Home, Tasks and supporting activity use recognizable icons for known sources such as GitHub, Slack and email. Icons have accessible names and hover labels. Task rows keep project, repository, workspace and account names visible and searchable. Unknown sources display their text. Connection controls name the provider for assistive technology even when its icon supplies the visual label.

- Task context renders Markdown headings, lists, emphasis, links, tables and fenced code offline. Raw HTML is inert, images make no network requests, and outbound approval previews retain their exact content.
- In Settings the user can edit the ignore list of named projects, GitHub repositories (owner/repo), and local checkout paths. Existing scopes remain visible for editing. A paused task shows its status.
- Home and Projects show **Ignore project** beside each named project. An explicit exclusion can be removed there. A child covered by a parent identifies the parent. In both task queues and suggestions, clicking a project or repository name opens its own details with the applicable ignore or unignore control. The task title opens the task independently. The names are individually keyboard accessible on narrow and wide screens. The queue’s **I** shortcut opens scope details. GitHub repository details include a link to GitHub, and local repositories show their checkout path. Task actions and the GitHub repository list also offer applicable exclusion controls. Before applying a change, show the exact project or repository and the effect on existing and future work. Changing one exclusion preserves all other entries.
- **Close task** in task details retires an open task locally and preserves its evidence. Closed tasks are available in the Closed filter and leave the Home queue. Legacy dismissed tasks remain accessible. An uncertain delivery must be reconciled before closure.

- On Home and Tasks, two tasks with the same title can be distinguished by their labeled project, repository when known, and source directly in the row. These labels wrap in a narrow window and appear in task details. A GitHub event identifies its owner/repository, a Slack event its channel when recorded, and an email event its originating mailbox account. Source information comes from the triggering activity even if a later action uses another account. A local task shows its project and Local. Only show a repository associated with the task itself. Queue search matches the displayed context.

- Task and activity filters for a named group include its child projects. The Global filter shows general work and All projects shows the complete workspace. The project editor lists its directly linked repositories and lets the user choose a parent for a named project. **Add repository** adds another row. For each row, **Choose folder…** opens the macOS directory picker. The chosen repository path appears in the form and is validated when the user saves. Users can replace or clear an existing selection. Cancelling preserves the form, including its current folder. The local browser interface also opens a native picker on the Mac running the service.
- Connect Google opens browser consent. After one Google account is connected, Add Google account opens a fresh account chooser. Reconnecting a particular row verifies its original identity. Manual registration remains available.

- Check Home with an empty workspace and with tasks, recent events and connected accounts. Empty sections show their empty states. In a populated workspace the counts match the queue, task and activity links open the corresponding views, and the Connections section offers exactly one action in either state.
- Selecting a row opens its project, status, source and recorded work. Filters and search update the displayed queue. Reported failures remain visible.
- Opening a task selects **Actions** and puts the available controls above the question, proposed change or result. **Why it surfaced & context** shows the reason, task Markdown, source and supporting evidence. **Task activity** shows its history, feedback and delivery receipts. The tabs support keyboard navigation. Switching tabs preserves the reviewed version and any stale-proposal warning.
- Home and Tasks offer shortcuts beside each task. Focus the row and press **A** to answer, **R** to retry preparation, **F** to give feedback, **C** to open the close confirmation, **V** to review a proposal or **O** to record a delivery outcome. Only applicable actions appear. The icon buttons show their keys on hover and work with touch. Review opens the exact version for a separate confirmation. Row shortcuts apply only while focus is on that task.
- A task waiting for an answer offers **Retry preparation** so the user can recheck its current project settings without entering the checkout path as an answer.
- **Settings → Folder access** is available even when the queue is empty. A question caused by an inaccessible checkout opens the same controls from **Allow folder access** on the task. The user can choose the registered folder again in a native picker, open macOS Files & Folders settings after a denial, or check access after changing a permission. Show the selected checkout path and verify Git can read it from the service before reporting success. A successful check wakes the existing scheduler for eligible tasks. Cancellation, choosing another folder and a failed check preserve project registrations and pending decisions.
- For a review, compare the displayed version, account, target and exact content with the submitted approval version. A stale or failed approval displays the server error. Delivery with an uncertain outcome offers no resend.
- Open a form while another task changes. Typed text and keyboard focus survive the refresh. A form submission reports failure inline and preserves the user's entry.
- A connection can be configured through the provider schema. A project rule can be saved, a skill reviewed, and a missed-work report submitted. A fresh state request reflects each successful action.
- With fixture accounts, connect GitHub without selecting a repository, connect Slack without a channel picker, and confirm a Google account with its granted services. Verify browser links, device codes, one-time app registration, cancellation, retry and reauthentication. Manual setup remains reachable for all three providers.
- A narrow window keeps all main views and actions accessible. A keyboard user can open and dismiss a form, navigate views and return to the invoking control.
- With one CLI installed, check that Settings distinguishes the installed and missing providers. Choose either provider, save, and reopen the editor. The selected provider persists and the delivery mode retains its saved value. Recheck after installation and verify that the status updates without discarding edits. A failed availability check offers a retry.
- Decline pending style guidance and observe its updated state. Open a completed report and follow a recovered task link to the matching task detail.
